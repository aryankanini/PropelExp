## Story Title
- Present actionable recovery errors
## Status
- **State**: WIP
- **Superseded By**: N/A
- **Change Request**: N/A
## Description
- As a reviewer, I want calm actionable failure messages, so that I know what failed, what remains safe, and what to do next.
- **Estimate**: 3 SP (24 hours)
## Acceptance Criteria
### AC-001: Actionable error state
- **Given**: A safe problem or terminal job failure reaches the UI
- **When**: The error state renders
- **Then**: It names the failed operation, retained work, retryability, correlation ID, and one primary recovery action
### AC-002: Accessible terminal announcement
- **Given**: The error is terminal
- **When**: It first renders
- **Then**: It is announced once as an assertive alert without exposing provider details or document content
## Edge Cases
- When no retry is allowed, the primary action is replacement, return, or later retry rather than a disabled retry control.
