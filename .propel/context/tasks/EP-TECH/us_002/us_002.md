## Story Title
- Publish the typed API contract

## Status
- **State**: Draft
- **Superseded By**: N/A
- **Change Request**: N/A

## Description
- As a feature developer, I want one versioned API contract, so that frontend and backend changes remain compatible.
- **Estimate**: 3 SP (24 hours)

## Acceptance Criteria

### AC-001: OpenAPI publication
- **Given**: The backend application starts successfully
- **When**: The OpenAPI document is requested
- **Then**: A versioned OpenAPI 3.1.0 document describes every REST, multipart, SSE, problem, and security operation

### AC-002: Contract drift detection
- **Given**: Frontend API types were generated from the contract
- **When**: A backend schema changes without regenerating those types
- **Then**: The contract compatibility test fails and identifies the changed operation or schema

## Edge Cases
- An SSE or multipart operation omitted from the contract causes the completeness check to fail.
