# User Story - US_003

## Story ID
- **ID**: US_003

## Story Title
- Validate runtime configuration at startup

## Status
- **State**: Draft
- **Superseded By**: N/A
- **Change Request**: N/A

## Description
- As an operator, I want runtime configuration validated before traffic is accepted, so that unsafe or contradictory settings cannot run.
- **Estimate**: 3 SP (24 hours)

## Acceptance Criteria

### AC-001: Valid configuration
- **Given**: All required environment settings are present and consistent
- **When**: The backend starts
- **Then**: Typed configuration exposes origins, bind addresses, ports, workspace, limits, credentials, provider settings, timeouts, and retention values

### AC-002: Invalid configuration
- **Given**: A required setting is missing or contradicts another setting
- **When**: Startup validation runs
- **Then**: Startup fails before the API accepts traffic and reports only the safe setting name and reason

## Edge Cases
- A provider marked approved without its required endpoint or key is rejected as contradictory configuration.
