# User Story - US_016

## Story ID

## Story Title
- Detect document type, extract and normalize text
## Status
- **State**: WIP
- **Superseded By**: N/A
- **Change Request**: N/A
## Description
- As a reviewer, I want each page analysed, routed to the best extraction method, and normalized, so that scanned and mixed documents remain reviewable.
- **Estimate**: 8 SP (64 hours)
## Acceptance Criteria
### AC-001: Document type detection and routing
- **Given**: A validated document is submitted for extraction
- **When**: The extraction pipeline starts
- **Then**: Each page is individually assessed for native text completeness and classified as native-text or OCR-required before any extraction runs
- **And**: The routing decision and classification reason are retained per page

### AC-002: Native text path
- **Given**: A validated page has complete native text
- **When**: Extraction runs
- **Then**: Native text and coordinates are retained without an OCR request
### AC-003: OCR fallback path
- **Given**: A validated page has missing or incomplete native text
- **When**: Extraction runs
- **Then**: Only that page is sent to the approved OCR port and returned text retains page coordinates
### AC-004: OCR failure path
- **Given**: OCR fails for a page
- **When**: The job records the response
- **Then**: The page and OCR stage are failed and no content from that page is confirmed
### AC-005: Text normalization
- **Given**: Raw text has been obtained from native extraction or OCR for a page
- **When**: Normalization runs
- **Then**: Whitespace, line breaks, encoding artifacts, and OCR noise are normalized before the text is passed to CMS structure detection
- **And**: Normalization does not alter the substantive content of the extracted text

## Edge Cases
- A mixed document may use native text and OCR on different pages without changing page order.
- A page whose normalized text is empty after artifact removal is treated as OCR-required rather than silently passed as blank native text.
